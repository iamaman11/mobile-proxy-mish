# Cloudflare integration boundary

This directory contains the two direct Cloudflare integration surfaces used by `mobile-proxy-mish`.

## Mesh / Zero Trust verification

The live Windows/Cloudflare Mesh prerequisites are verified through the official Cloudflare API by:

```text
.github/workflows/cloudflare-live-preflight.yml
```

Cloudflare remains the live Mesh configuration authority. The actual device Mesh address is runtime state and is never hard-coded as a universal proxy endpoint.

## Unified CONTROL Worker

The authenticated control plane lives under:

```text
infra/cloudflare/control-worker/
```

It is deployed directly with Wrangler and owns only:

- the `mish-device-control` Worker;
- one fixed-name `DeviceControl("primary")` Durable Object for this single-device deployment;
- the unified hostname `mish.alegria.by`;
- the Worker secret `MISH_MANAGER_TOKEN`.

The Android device authenticates the one outbound WSS session with its non-exportable Keystore P-256 key. Rust/Tokio remains the sole reconnect/heartbeat and PRODUCT command owner.

The external consumer knows only:

```text
host  = mish.alegria.by
token = MISH manager Bearer token
```

It never supplies `device_id`, `request_id`, `operation_id`, credential version, Mesh epoch or WSS details.

## Public API

### Current proxy connection

```text
GET https://mish.alegria.by/v1/proxy
Authorization: Bearer <MISH_MANAGER_TOKEN>
body: none
query: none
```

Success schema:

```text
mish.proxy/v1
```

A ready response contains:

```text
ready=true
host=<current admitted Mesh endpoint>
ports.mixed=1080
ports.socks5=1081
ports.http=3128
username=<current running proxy credential>
password=<current running proxy credential>
```

The Worker does not own or synthesize any of these facts. The device assembles a fail-closed read from the current Readiness, Transport and Proxy owners.

The proxy read is intentionally not a state machine:

```text
HTTP GET
 -> Worker auth
 -> live primary DO
 -> existing authenticated WSS
 -> GET_PROXY(internal request_id)
 -> device reads current owner facts
 -> PROXY(...)
 -> HTTP response
```

The internal request id is generated by the Worker and never appears in the public proxy response.

Proxy response correlation exists only in memory while the HTTP request is alive. Proxy endpoint, username and password are never written to Durable Object storage. There is no offline queue, no retry loop and no ADB fallback.

Unavailable responses contain no partial credentials.

### Rotate public IP

```text
POST https://mish.alegria.by/v1/rotate
Authorization: Bearer <MISH_MANAGER_TOKEN>
body: empty
```

The existing schema remains:

```text
mish.control.rotate/v1
```

One public POST represents one logical Rotation. The Worker generates internal correlation and never creates a second Rotation owner.

Current accepted CONTROL timing/safety boundaries remain:

- Rust/Tokio heartbeat interval: 4 s;
- Worker fresh-session window: 10 s;
- initial delivery ACK boundary: 2 s;
- manager HTTP ceiling: 18 s;
- accepted/fail-closed drain: 120 s;
- on one lost initial ACK, only a natural authenticated Rust reconnect may redeliver the same request id once.

`socket.send()` is not delivery proof. `ACCEPTED` remains the authoritative mutation-start boundary because PRODUCT sends it before activating Rotation.

## Local and remote consumers

Local Windows agents and remote clients use the same public API:

```text
GetProxy() -> GET /v1/proxy
RotateIp() -> POST /v1/rotate
```

ADB provisioning remains an explicit bootstrap/maintenance path only. Normal local operation must not silently fall back to ADB.

## Boundary

There is no second configuration engine, mutable proxy mirror, device registry, manager polling loop, offline command queue, Workers VPC dependency, Android inbound listener, second rotation owner, second PRODUCT state database or generic remote-command framework.

Cloudflare transports and correlates. PRODUCT owners on the device remain authoritative.
